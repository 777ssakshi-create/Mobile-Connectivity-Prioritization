# Recommended Power BI Information Architecture

The enhanced HTML dashboard is the portfolio prototype. A production Power BI version should use three pages so executive and assurance information are not overcrowded.

## Page 1 — Executive Prioritisation

Purpose: answer *where should we focus first?*

Recommended visuals:

- KPI: markets assessed
- KPI: higher-priority markets
- KPI: estimated population represented by positive benchmark gaps
- KPI: high-confidence data coverage
- Global market-priority map
- Top 10–12 priority markets
- Usage-gap vs population-impact scatter
- Executive insight / selected-market callout

Recommended slicers:

- Priority band
- Data confidence
- Diagnostic segment
- Market search / country

## Page 2 — Market Deep Dive

Purpose: answer *why is this market prioritised?*

Recommended content:

- Priority score and rank
- Internet usage
- Benchmark gap
- Estimated population impact
- Rural population share
- GDP per capita
- Mobile subscriptions per 100 people
- Data-confidence category
- Observation years for each metric
- Score-component decomposition
- Base vs alternative rank
- Diagnostic / next-investigation statement

## Page 3 — Decision Assurance & Methodology

Purpose: answer *how much should we trust the prioritisation?*

Recommended content:

- Confidence-category distribution
- Observation-year freshness / spread
- Base vs alternative weighting comparison
- Markets with largest rank changes
- Scoring weights and formulas
- Indicator definitions
- Assumptions and limitations
- Portfolio disclosure

## Visual design principles

- Use a restrained executive palette with a strong neutral background.
- Reserve red/amber/green semantics for risk/priority/confidence only.
- Use consistent number formatting and explicit units.
- Avoid pie/donut charts when rank or magnitude comparisons are more important.
- Surface data freshness and confidence close to the decision, not only in a methodology page.
- Keep disclosures visible without overwhelming the executive page.
